# 任组学术 PPT

目标不是“把内容塞进模板”，而是把科学问题、证据和结论组织成清晰、统一、可讲述的学术演示。

## 资源与优先级

- 默认从 `assets/RenGroup-PPT-template.pptx` 开始，保留其 16:9 页面尺寸、母版、页码和视觉识别。
- 内置模板使用 [template-map.md](references/template-map.md) 选择版式；用户提供更新模板时，以实际模板结构为准，不套用旧页码映射。
- 完整视觉规则见 [style-guide.md](references/style-guide.md)；逐页验收见 [qa-checklist.md](references/qa-checklist.md)。
- 用户模板的母版、布局和继承样式优先于内置模板的数值参考；若项目仍要求任组固定字体等硬规范，则继续执行对应规则。
- 不脱离模板另造一套主题，也不为了“更现代”替换组内视觉身份。

## 工作流程

### 1. 先做科学叙事
先理解材料、受众、时长和最终要回答的问题，再确定页面结构。默认采用：

`问题 / 背景 → 方法 / 设计 → 关键证据 → 解释 / 对比 → 结论 / 展望`

每页只推进一个主要信息。标题尽量表达本页主题或结论，而不是泛化成“Results 1”“实验结果”等。

不得虚构实验结果、样本量、误差、显著性、引文、模型性能或未提供的事实。证据不足时明确标注待补充。

### 2. 再做模板映射
先为每页确定“页面任务”，再选择模板布局：
- 流程/三组对比；
- 窄图 + 解释；
- 宽图/表 + 解释；
- 章节导航；
- 总结/展望。

优先复制现有模板页并替换内容。只有现有布局无法清楚表达时才新建布局，并继续继承母版和组内样式。

### 3. 完整实现
- 清除所有示例标题、图片、表格、姓名、日期、`xxx`、示例引文和占位结论。
- 图、表、文字按“证据优先”组织；结果页尽量让图表承担主要信息。
- 结论框用于解释本页证据及其意义，不重复标题。
- 内容过多时精简或拆页，不通过缩小关键文字强行塞入。
- 保留原始数据含义、单位、误差、图例和必要来源信息。

### 4. 结构审计
运行：

```bash
python scripts/audit_ppt.py output.pptx
```

若使用用户模板：

```bash
python scripts/audit_ppt.py output.pptx --template path/to/template.pptx
```

内置模板执行严格组内样式检查；自定义模板下固定样式差异默认降为警告，避免把旧模板数值误判成新模板错误。只有明确需要继续强制旧组内样式时使用 `--strict-style`。

审计脚本是结构检查器，不等于视觉验收；警告必须结合实际页面人工判断。

### 5. 真实视觉验收闭环
必须尽可能形成：

`实现 → 结构审计 → 渲染全部页面 → 全局缩略图检查 → 逐页检查 → 修正 → 再审计 / 再渲染`

重点检查信息层级、标题与页码、字体、图表可读性、裁切/重叠、留白、对齐、结论框、残留模板内容和跨页一致性。最后一次修改后仍应重新渲染；未查看最终渲染结果时，不得声称“已完成逐页视觉质检”。

## 不可妥协的科学表达

- 每页一个主要结论或问题，不做实验流水账。
- 对比页明确基线、方法、指标和改善方向。
- 不确定性、样本量、验证设计和限制会影响解释时必须展示。
- 图注、引文和来源靠近对应证据；不能用不存在的引用填空。
- 科研准确性高于装饰效果和页面“饱满度”。

## 任组视觉底线

在内置模板和现行组内规范下：
- 中文黑体，英文与数字 Arial；
- 内容页标题顶部居中并继承模板深红色；
- 正文和结论保持演示距离下可读；
- 结论框沿用模板红色虚线圆角框；
- 表格默认不使用彩色单元格填充；
- 图表文字、坐标轴和图例必须可读；
- 内容页左下角不新增日期或研究周期；
- 背景保持干净，不添加无关渐变、深色面板或重装饰。

精确字号、颜色、间距和图像要求见 style guide，不在主 skill 重复维护。

## 交付标准

只有同时满足以下条件才可交付：
1. 科学内容与来源没有明显遗漏或虚构；
2. 结构审计中的错误已解决，警告已人工核对；
3. 全部最终页面已实际渲染并检查；
4. 最新一轮修改后完成复验，没有残留模板内容、重叠、裁切或关键可读性问题。

最终回复只需说明文件、关键设计/内容改动、审计与渲染结果，以及仍需用户补充的科学信息。
