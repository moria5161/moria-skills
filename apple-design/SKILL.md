# Apple 风格界面设计

## 目标

创建冷静、精确、克制、连贯且具有平台原生感的界面。不要把 Apple 风格简化为圆角、模糊和灰白配色；层级、内容密度、交互反馈、无障碍和平台习惯同样重要。

最终结果应像经过推敲的产品，而不是套用视觉效果的通用模板。

## 工作流程

### 1. 明确产品任务
先确定目标平台、核心用户任务、主流程、信息密度、浅/深色需求、现有框架与设计系统，以及用户需要“受 Apple 启发”的原创界面还是严格遵循 Apple 平台规范的原生界面。主流程不清楚时不要直接编码。

### 2. 检查现有项目
修改前读取仓库结构、组件、设计令牌、构建方式和现有业务逻辑。优先复用已有依赖、图标体系和组件，不因视觉改造无故替换框架或架构。

### 3. 确立单一设计方向
形成一致的布局骨架、字体层级、表面层级、交互模型和动效语言。不要混用 Apple、Material、赛博朋克、重度玻璃拟态和通用 SaaS 风格。

### 4. 完整实现
实现真实可用界面，而不是静态样稿。根据任务覆盖响应式、空/加载/错误状态、完整控件状态、键盘操作、触控目标、屏幕阅读器语义、减少动态效果，以及适用时的浅色/深色模式。

### 5. 真实视觉验收闭环
实现任务必须尽可能形成：

`实现 → 启动/构建 → 实际渲染 → 截图检查 → 修正 → 再渲染复验`

至少检查主桌面尺寸和一个较窄视口；若产品明确支持深色模式或关键特殊状态，也应检查对应状态。重点复核：
- 对齐、留白、字体层级和内容密度；
- 长文本、真实数据、空状态和异常状态；
- 溢出、遮挡、裁切和横向滚动；
- 控件默认/hover/pressed/focus/disabled/loading 状态；
- 对比度、键盘路径、触控尺寸；
- 材质、阴影和动效是否真正服务层级。

未查看真实渲染结果时，只能说明“代码实现/静态检查完成”，不要声称“视觉精修完成”。如果当前环境无法渲染或截图，应明确说明限制。

视觉检查细则见 [visual-review.md](references/visual-review.md)。

## 核心原则

### 清晰与内容优先
让用户快速理解当前位置、重要信息、下一步操作和操作结果。优先用层级、位置、邻近关系和空间节奏表达结构，不依赖大量边框、标签或卡片。

装饰必须服务内容；科研数据、表格、参数和长文本的准确性与可读性高于“像 Apple”。

### 克制且一致
减少但强化设计决策。统一字体、间距、圆角、控件高度、图标、表面和过渡；相似元素必须具有相似行为。

玻璃、阴影、缩放和动效只用于表达层级、空间关系或状态变化，不作为默认主题。

### 平台与现有系统优先
本 skill 中出现的尺寸、时间、圆角和宽度都只是经验参考，不是硬规范。优先级通常为：

`平台原生规范 / 项目现有 Design System / 产品实际内容与密度 > 本 skill 参考值`

不要为了满足某个参考数字破坏现有系统的一致性。

## 实现约束

- 卡片只用于真实对象边界或交互边界，不要“万物卡片化”。
- 从中性表面和少量强调色开始；语义色只在真正传达含义时使用。
- 半透明材质更适合工具栏、侧边栏、导航、浮层和临时上下文；正文、表格和高密度信息优先实色表面。
- 输入框要有可见标签、聚焦和验证反馈；危险操作要明确，不只靠颜色区分。
- 每个交互控件根据需要实现 default、hover、pressed、focus-visible、selected、disabled、loading。
- 图表和表格优先保证扫描效率、标签准确和数据可读性。
- 无障碍是默认要求：语义结构、键盘导航、可见焦点、可访问名称、足够对比度、合理触控区域、非颜色依赖状态表达。
- 支持 `prefers-reduced-motion`；较长动效必须可被用户输入中断。
- 不打包或分发 Apple 专有字体、商标、产品图或专有资产，也不要暗示与 Apple 存在无依据关联。

Web/桌面端的布局、字体、材质、控件和动效参考见 [web-design.md](references/web-design.md)。SwiftUI 与 Apple 原生平台实现见 [apple-native.md](references/apple-native.md)。

## 科研与专业软件

Apple 风格的克制不能隐藏重要技术信息。优先保证：
- 数据、参数、实验和文件上下文清楚；
- 图表、表格和日志可读；
- 工作流非破坏、进度可见、错误可恢复；
- 导入、导出和状态反馈明确。

常见结构可以是“侧边栏 + 主工作区 + 检查器 + 状态区”，但以实际任务为准，不机械套模板。

## 必须避免

除非用户明确要求，不要使用：
- 紫蓝渐变、霓虹发光、重度玻璃拟态；
- 到处漂浮的卡片、随机色块、装饰性 3D 对象；
- 应用界面的超大 Hero 标题；
- 过量胶囊、徽章、阴影、边框和动效；
- 多个竞争性强调色或低对比小灰字；
- 无意义指标、占位图表和通用 SaaS 仪表盘；
- 用卡片替代表格或隐藏关键操作；
- 像素级复刻 Apple 官网或复制其专有资产。

## 最终交付

实现已被要求时，不要停在设计描述或多个薄弱方案。交付前确认代码可构建/运行、关键流程未被破坏，并完成可行的视觉复验。

最终只总结：关键改动、实际验证结果、仍存在的环境或产品限制。
