# Codex Research

将研究问题、实际实现、实验执行和结论连成可核查的证据链。项目规则和本次用户要求决定具体协议；本 skill 不指定模型、路径、硬件、seed 或训练预算。正式实验默认使用项目内稳定、可读的语义 ID，而不是单调数字编号。

## 0. 新项目初始化（必须执行）

用户给定新研究项目并调用本 skill 时，必须实际建立记录体系，不能仅提出建议或提供模板。创建这些文档是项目接手的默认工作，不额外请求确认；用户明确要求只读或不建文档时遵循该要求。

1. 确认用户指定的项目根目录，先读已有适用规则、README、目录结构、配置及本次会话，提取项目目标、研究入口、约束和当前状态。
2. 检查并补齐以下三份主文档：

   ```text
   <项目根目录>/
   ├── AGENTS.md                 # 强制规则、项目边界与维护合同
   ├── EXPERIMENTS.md            # 固定四模块、表格化实验账本
   └── SUMMARY.md                # 当前交接、关键决定、状态与证据入口
   ```

3. 可运行 bundled script 创建缺失文件：

   ```bash
   python <skill目录>/scripts/init_research_project.py --project <项目绝对路径> --date <项目时区的当天YYYY-MM-DD>
   ```

   脚本只创建缺失文件，不覆盖已有文件；它只生成初始结构，不能代替后续阅读和内容提炼。脚本拒绝把符号链接或非普通文件当作可写文档；此时核实真实目标，避免写错项目。
4. 读取[记录模板](references/record-templates.md)，将实际提炼内容写入文档：AGENTS写必须长期遵守的硬约束、执行边界和项目特定规则；EXPERIMENTS保持“研究主线 / 实验 idea 与设计 / 结果与讨论 / 下一步”四个模块不变，以表格为主体、只保留必要文字；SUMMARY承担全部跨会话交接、关键决定、状态变化和证据入口。
5. 未核实内容写“待确认”或“尚未核实”。不得把模板占位、空表或脚本成功当作接手完成，不从别的项目复制训练配置、执行授权或仓库权限。
6. 文件已存在时先读再按分工增量合并，保留原有规则和历史。若项目已有旧的 `history/` 记录，只把它作为遗留证据按需读取；默认不再创建新日文件、不维护索引，也不擅自删除旧记录。
7. 初始化验收：三份主文档均存在且可读，初始化日期/项目事实正确，内部链接有效，SUMMARY含实际交接信息，EXPERIMENTS维持固定模块且主要内容表格化，已有文件未被覆盖。最终回复链接三份主文档。

## 1. 接手与任务范围

1. 定位项目根目录，读取适用的 `AGENTS.md`、`SUMMARY.md`；涉及实验时再读取 `EXPERIMENTS.md`。缺失时先执行第0节初始化；名称不同时通过标准入口链接项目已有等价文件。
2. 涉及实验时读取实验账本、对应配置、实际代码和 SUMMARY 中相关决定/理由；若旧 history 中存在唯一证据，再按需读取，不把它恢复为日常记录机制。
3. 核实当前分支、工作区改动、真实路径、符号链接、权重、结果及任务状态。摘要是线索，不能代替实时检查。
4. 明确用户要交付的是解释、诊断、实现、冒烟、正式训练、评估还是清理。已有有效授权持续生效；诊断授权不能自行扩展为正式训练或 test，待办和旧历史不提供新授权。
5. 在授权范围内自主完成可逆工作、实现和必要验证，不反复询问已明确的事项。关键协议缺失且会改变研究结论时先准备不依赖该决定的工作，再问最小必要问题。
6. 保留用户指定的基线和模块，采用符合项目风格的最小修改；不顺手重构或修复无关问题。

## 2. 研究问题与实验合同

实现前写清：基准是什么、核心变量是什么、想验证什么、哪些观测支持或反驳假设。

- 默认一次对照一个核心变量；用户允许多变量时逐项披露，不声称单因素因果。
- 固定数据来源/revision/hash、划分、预处理、模型和初始化、优化器、训练预算、精度、硬件、seed与选模指标。
- 固定评估端点、源码版本、输入条件、样本身份与顺序、候选池、解码/排序、计分函数、分母及排除规则。
- 区分假设、提案、已冻结配置和已执行事实；缺失参数明确标注，不将默认配置或旧快照直接当新实验模板。
- 区分 epoch、更新次数、全局 batch、每卡 batch、梯度累积和样本曝光量。改变卡数或 batch 可能改变负样本池与预算，不能自动视作纯加速。
- 正式实验默认使用稳定语义 ID，而非 `E001`、`P003` 这类只表达顺序的编号。推荐结构为 `<Track>-<Scope>-<Variant>[-<Qualifier>]`：Track 表示研究主线/任务，Scope 表示数据、域、模型或作用范围，Variant 表示核心机制或对照变量，Qualifier 仅在前三段不足以唯一表达实验时添加。具体词汇由项目语义决定，不强制固定枚举。
- 语义 ID 应让人脱离表格也能快速判断“做什么、在哪做、核心改了什么”，例如 `Align-Mols-Base`、`Gener-SDBS-Mix`、`Review-Mols-Transfer`；避免 `Exp-New`、`Final2`、`Try3` 等低信息名称。
- 实验 ID 与运行 ID 分离：实验 ID 描述研究设计，seed、日期、GPU、job ID、checkpoint、重跑/恢复序号属于运行元数据。同一设计的多 seed、resume 或重复运行共享实验 ID，但每次运行必须有可追溯的独立运行标识和产物路径。
- 正式实验一旦形成证据链，语义 ID 默认保持稳定，不能因结果好坏或先后顺序改名。只有名称明显误导、发生体系迁移或用户明确要求时才重命名。
- 从旧数字编号迁移到语义 ID 时，先建立 `旧 ID → 新语义 ID` 映射，再同步核对配置文件、启动脚本、checkpoint/权重、结果目录、TensorBoard、日志、manifest 与文档引用。若用户要求“仅改命名”，不得顺带改变模型、数据、训练或评估计算；迁移后检查是否仍有旧引用并在 SUMMARY 保留映射。
- 冒烟、测速和一次性诊断可使用明确的非正式运行名，不占用正式实验 ID；若后续升级为正式实验，再赋予稳定语义 ID。

必要时使用 [实验与交接模板](references/record-templates.md)，只填写与任务有关的字段。

## 3. 数据隔离与可比性

- train 用于参数更新；valid 用于按合同选模和允许的诊断；test 用于预定协议的最终评估。test 不选模、调参、筛样本或决定重采样权重。
- 改训练方法不自动授权改评估口径。比较基线时逐项核对数据、输入信息、初始化、预算和评估；差异无法控制时保留限定结论。
- 缺少本地同协议复跑，不能写成论文未报告基线；无法取得逐样本清单，也不能写成已经发现协议不同。
- 区分 loss、token/patch 指标、样本准确率、检索召回率和有效率；不同分母不能直接相减或互换。
- 预先固定评估 checkpoint。若项目要求同时报告 valid-best 与最终 last，分别标注选择指标、epoch/step 和 hash；不得按 test 结果挑端点。缺失 best 如实记录，不用 test 补选，也不自动重跑全部历史实验。
- 权重形状兼容不证明预处理、分词器、特征语义或标签空间兼容；比较正文 token 与接口包装时分开检查，不能因包装不同误判语义不同。
- 缓存须绑定数据、模型、预处理、顺序及候选 hash；任何依赖变化先明确失效范围，不静默复用。
- 样本身份按协议保持，重复输入或同表示不同标签只做诊断分组，不擅自去重、补真值或缩小 valid/test 分母。

## 4. 实现与分阶段验证

按风险选择最小必要验证，已经通过后不为凑数量重复测试。低影响文档调整通常只需结构、链接和差异检查。

1. 静态核对配置、入口和真实调用链。启动包装脚本可能运行冻结源码快照，修改工作区不等于修改正在运行的任务。
2. CPU 语义检查覆盖研究机制：损失方向、候选顺序、冻结范围、数据隔离、基线退化条件及恢复语义；不要只测试实现自身的重复描述。
3. 在获授权且需要时进行真实数据/权重冒烟：前向、有限梯度、实际开放参数、显存、完整 valid、保存加载和恢复。诊断不混入正式训练曲线。
4. 冻结模块同时检查梯度、参数变化、运行模式及共享 storage；不能仅凭 `requires_grad=False` 宣称完全独立或冻结正确。
5. 蒸馏/辅助损失先用允许的 train 诊断核对分数、温度、loss 与加权梯度尺度；教师 train 提升不能证明泛化优势，教师 valid 无优势也不能证明未运行的蒸馏必然失败。
6. 对数值问题分别检查 raw/prob 排序、精确和近饱和、并列处理、输入重复、表示碰撞与真实纠错。子组重叠不能相加作为因果分解。
7. 分布式训练逐项检查全局配对、gather 梯度路径、各损失归约与 world-size 补偿；不能给不同损失一律乘同一系数。检查 valid 覆盖、无重复遗漏、恢复与单/多卡等价性，测速结论必须来自实际对照。
8. 报告实际通过、失败、跳过和未执行的范围；不将局部通过称为全仓通过，不为消除报错扩大容差或改变研究协议。

复杂任务按需读取 [执行、核验与清理检查表](references/execution-checks.md)。

## 5. 执行、完成与结论

- 使用项目规定的调度器或计算方式；明确申请 GPU/CPU/内存/时间，按已有授权执行，不从别的项目继承节点白名单或提交许可。
- 正式运行绑定 commit 或源码 hash；存在未提交改动时保存实际 diff/快照，不只记录一个不能代表运行内容的 commit。
- 结果使用独立路径，避免覆盖已有正式输出；共享存储空目录、排队和锁文件的存在均需按实际语义判断。
- 提交成功、排队、首轮成功、训练完成、评估完成分别记录。阶段性 `results.json` 或任务从队列消失不足以证明全任务完成。
- 完成须核对预期终点、完整结果、覆盖数、完成标记和必要 hash。调度器历史不可用时用产物证据核验，不编造退出码。
- 论文比较先核对正式正文、补充材料、指定版本代码和数据条件；旧版图号、模态、额外信息或预训练设定不能直接套用。需要外部核验时依据环境提供的搜索规则访问原始来源。
- 结论区分实现正确、当前设置有效、统计支持和可推广性。报告绝对变化、百分点、命中数及适当配对统计；小样本、单 seed、预算/恢复差异和未核实协议限制须保留。
- 测速同时报告阶段、硬件、精度、batch 和测量范围，不把局部加速写成整体或架构因果收益。

## 6. 恢复与产物清理

- 区分模型权重、完整训练状态、损坏输入、恢复副本和重复序列化。文件 hash 不同不证明张量不同；需要确认模型重复时比较对应张量。
- 恢复核对模型、优化器、scheduler、epoch/step、选模状态和 RNG；缺 RNG、重置部分优化器或改变配置时明确非逐位恢复及其影响。
- 部分恢复须在已有授权范围内进行，记录保留/重置范围、校验方法和下一步验证；不承诺“无损”。
- 删除前核对真实目标、符号链接、实验 ID/旧别名、脚本/配置/manifest 依赖及正在运行的任务。不能仅根据 `tmp`、`err`、旧名称或目录命名判断产物无用。
- 释放空间按用户明确范围永久删除；先保存必要失败/恢复说明和指标，确认保留正式端点及依赖。元数据归档无法恢复已删除权重本体，必须说明实际可恢复性。
- 区分 `du` 分配空间变化和共享文件系统 `df` 变化；同盘移动备份不释放空间。
- 用户授权清理后完成精确删除与核验，不反复请求确认；运行源码快照和正在写入日志不可随意清理。明确删除的历史或本体不能为“补全记忆”重新恢复。

## 7. 三层记录与跨会话交接

首次接手先执行第0节；随后持续维护三份主文档。采用以下分工：

| 层 | 主文件 | 内容 | 更新方式 |
| --- | --- | --- | --- |
| 强制规则 | `AGENTS.md` | 不随单次实验变化的硬约束、执行边界、数据/评估底线、文档维护合同 | 规则或长期边界变化时更新 |
| 实验账本 | `EXPERIMENTS.md` | 研究主线、idea/设计、主要结果/讨论、下一步 | 设计、状态或结果变化时更新 |
| 滚动交接 | `SUMMARY.md` | 当前状态、最近决定、关键理由、ID 兼容映射、风险与证据入口 | 每轮有实质交接信息时合并更新 |

- `EXPERIMENTS.md` 的四个模块保持固定，不继续扩展层级；主体使用紧凑表格，文字只用于解释协议、结论和限制，避免写成实验日记。
- 每轮最终回复前实际维护记录，包括纯讨论：将新决定、理由、更正、状态变化、未解决项和有效证据直接合并进 `SUMMARY.md`；不再创建 `history/YYYY-MM-DD.md` 或维护 `history/README.md`。
- 有设计或结果变化时同步更新 `EXPERIMENTS.md`；有底层强制规则或长期执行边界变化时更新 `AGENTS.md`。没有变化的文件不为凑更新而改写。
- `SUMMARY.md` 是唯一跨会话摘要入口：允许滚动压缩，但删除旧文字前必须把仍影响后续工作的决定、理由、失败、比较限制、恢复限制和证据入口保留下来。
- 区分已核实、历史状态、待确认、提议和未授权；动态状态标核实时间，未重查就明确写历史状态。更正注明新结论及来源，不改写成“当时就知道”。
- 旧项目已有的 `history/` 默认只读兼容；不得为了符合新结构主动删除，除非用户明确授权迁移或清理。
- 不保存密钥或无关隐私，不承诺后台自动记录、自动加载或完整记忆；读取/更新失败如实说明。

## 8. 提交与交付

遵循本项目已有提交/推送授权，不将某个项目的自动 push、分支或远程规则推广到新项目。获持续授权后无需每轮确认。

提交前检查分支、远程、diff、忽略规则及暂存文件，只纳入本次改动，保留已有无关工作。通常提交代码、配置及允许的文档；数据、权重、缓存、日志和逐样本输出是否提交由项目规则决定，不擅自上传。先统一完成本轮记录再提交，避免为记录提交号循环提交。推送后核对远程；失败如实报告，不强推、不自动合并或推向未经授权的上游。

最终回复先说明交付和发现，再说明关键验证、结论限制及尚未执行的事项。文件与证据用可访问链接，不要求用户阅读折叠的进度消息才能理解结果。
