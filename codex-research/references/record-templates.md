# 实验与交接模板

首次接手必须建立三份主文档、历史索引和当天记录；下列模板用于实际写入，并用已核实内容填充。保留项目已有规则和语言偏好。摘要建议约2,500汉字以内，主账本建议约6,000字符以内；这些是阅读目标，不得为了达标删掉唯一证据、映射或比较限制。长细节归档后链接。

## 项目规则（AGENTS.md）

```markdown
# 研究工作约定

## 接手与范围
- 每轮先读本文件、SUMMARY.md和history/README.md；实验任务再读EXPERIMENTS.md、配置与实际代码。
- 摘要和历史不是实时事实或执行授权，使用状态和路径前核实。
- 遵守当前用户要求与已明确项目边界；未知协议标注待确认。

## 实验与评估
- 实验先记录基准、核心变化、假设及冻结配置；多变量差异明确披露。
- train更新、valid选模、test按固定协议评估；不得用test挑权重或调参。
- 保留ID、源码、配置、权重、评估和结果证据链。
- 资源、seed、预算、编号及提交推送策略按本项目实际约定，不从别的项目继承。

## 记录维护合同
- AGENTS维护固定规则，EXPERIMENTS维护设计及主要结果，SUMMARY维护当前交接，history按日维护决定与理由。
- 每轮最终回复前：提炼当天重要讨论至history/YYYY-MM-DD.md、更新索引和SUMMARY；设计/结果或规则改变时更新对应主文档。
- 覆盖摘要前先归档唯一信息；历史更正注明日期和来源，旧历史不因跨日被覆盖。
- 不保存密钥，不虚构理由，不承诺后台自动记录；写入失败如实说明。

## 项目特定约定
<仅写实际核实或用户明确的约束；未确定项明确标注>
```

## 每日决策历史

```markdown
# <YYYY-MM-DD>
记录/补录：<时间>；来源：<本次决定/旧文档/commit>；范围与不完整性：<说明>

## <主题>
- 决定：<用户要求或最终采纳的行动>
- 理由：<实际讨论或证据，不自行补造>
- 替代方案：<讨论过的方案及取舍，没有则省略>
- 已执行：<实际结果与核验范围>
- 限制/未解决：<失败、协议偏差、授权与恢复边界>
- 证据：<源码版本、配置、manifest、结果入口>
- 后续更正：<更正时间与链接，没有则省略>
```

历史索引按日期和主题链接，说明历史状态不是实时监控、待办不提供授权。不要把每日记录变成全文聊天转储。

## 实验 manifest 最小字段

- 稳定实验ID、实际运行名、父实验和核心变量。
- commit、dirty diff/源码 hash、启动命令及冻结配置。
- 数据版本/hash、划分数量、预处理/分词版本和身份顺序。
- 初始化与评估权重 hash、epoch/step、选模指标和 best/last 定义。
- batch、卡数、累积、更新预算、seed、精度、硬件与环境。
- 候选/case hash、解码与计分、分母与跳过规则。
- 任务ID、开始/结束时间、结果路径、完整覆盖及完成校验。
- 恢复、协议例外和当前可恢复性；未知项明确写未知。
